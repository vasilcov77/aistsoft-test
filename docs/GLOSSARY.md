# Глоссарий проекта

Термины, принятые в проекте REST API для checko.ru. Фиксируют общий язык между разработчиком
и комиссией.

## Слои и компоненты

- **Transport (точка доступа с ресурсами)** — единый entry point для внешних запросов, обёртка
  над Guzzle. Отвечает за HTTP-транспорт, таймауты и ретраи. Работает с абстракцией
  `ResourceInterface`, не зная о доменных деталях.

- **Resource (стратегия)** — класс, инкапсулирующий один эндпоинт checko. Реализует
  `ResourceInterface` и знает свой путь (`getPath`), как строить тело запроса
  (`buildParams`) и как мапить ответ в DTO (`mapResponse`). Паттерн Strategy: один класс =
  один ресурс.

- **Facade / Client** — оркестратор конвейера: валидация входа → маппинг параметров → вызов
  Transport → кэш → маппинг ответа. Управляет политикой ретраев и переводит транспортные
  ошибки в доменные исключения.

- **DTO (Data Transfer Object / Value Object)** — неизменяемый (_immutable_) объект данных,
  который валидирует себя при создании: отклоняет некорректные входные данные (напр. плохой
  ИНН).

- **API layer** — HTTP-слой проекта: роутер + контроллеры под префиксом `/api/v1/`, отдающие
  JSON.

## Данные и модели

- **Ресурс checko** — эндпоинт API checko (`/company`, `/entrepreneur`, `/contracts` и т.д.).
  У каждого свои обязательные параметры (`inn`; у `/contracts` — `law`, `role`, `sort`).

- **Ключ (API key)** — параметр авторизации checko, передаётся в теле запроса. Хранится в
  переменной среды (`env`).

- **Идемпотентность** — свойство запроса: многократное выполнение даёт тот же результат,
  что и однократное. К запросам в checko не применяется: все они — `POST` и тарифицируются,
  поэтому повторный вызов — осознанное решение клиента, а не автоматический retry.

## Ошибки и надежность

- **Ретрай** — повторный запрос при сбое. В проекте применяется только на таймаут/ошибки
  соединения (`ConnectException`), 3 попытки с экспоненциальной задержкой. 5xx от checko не
  ретраим: они не оплачиваются, но повтор только задерживает ответ.

- **Timeout (таймаут)** — превышение времени ожидания ответа от checko; обрабатывается ретраем,
  затем поднятием `TimeoutException`.

- **ExceptionHandler** — единый обработчик внизу роутера, переводящий доменные исключения в
  HTTP-ответы вида `{ "error": { "type", "message", "code" } }`.

## Инфраструктура

- **Valkey** — in-memory хранилище (форк Redis) под кэш ответов checko. Доступ через
  абстракцию PSR-16, чтобы не привязывать домен к конкретному бэкенду.

- **TTL (время жизни)** — сколько живёт запись в кэше. В проекте — 15 минут для всех
  ресурсов, константа в конфиге (см. [ADR-0002](adr/0002-cache-policy.md)).

- **Ключ кэша** — `checko:v2:<resource>:<sha256(параметры)>`. Параметры нормализуются
  (сортировка по ключу), ключ checko в ключ кэша не входит.

- **Лимит запросов** — у checko 32 запроса в секунду с одного IP (сверх — `429`) и 100
  бесплатных запросов в сутки; платные — только ответы `200`.

- **meta** — служебный блок ответа checko: `status`, `today_request_count`, `balance`,
  `message`. Признак успеха — `status = "ok"` (см. [checko-api-errors.md](checko-api-errors.md)).

- **PSR-16** — стандарт простого кеша (Simple Cache). Абстракция, позволяющая заменить Valkey
  на другой бэкенд без правки домена.

- **swagger-php** — генерация OpenAPI-спецификации (`openapi.yaml`) из аннотаций над
  контроллерами.

## Зависимости

- **Guzzle** — HTTP-клиент (ретраи, таймауты, middleware).
- **PSR-4** — стандарт автозагрузки классов.
