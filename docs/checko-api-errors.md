# Контракт checko API и распознавание ошибок

Как обёртка понимает, что ответ checko — успех, а что — ошибка. Составлено по официальной
документации (https://checko.ru/integration/api) и проверено живыми запросами.

## Формат ответа

Тело ответа всегда JSON с двумя блоками:

```json
{
  "data": { "...": "полезные данные ресурса" },
  "meta": {
    "status": "ok | error",
    "today_request_count": 12,
    "balance": 1000.0,
    "message": "текст ошибки"
  }
}
```

- `meta.status` — единственный надёжный признак успеха/ошибки в теле.
- `meta.message` — человекочитаемая причина, годится для лога и текста нашего 502.
- `meta.today_request_count`, `meta.balance` — служебные метрики, в DTO не попадают.

## Признак успеха

`HTTP 200` **и** `meta.status = "ok"` — только такой ответ кэшируется и тарифицируется checko.

## Распознавание ошибок

Порядок проверки в Transport:

1. Сетевой сбой/таймаут (`ConnectException`) → ретрай (3 попытки), затем `TimeoutException`.
2. HTTP-код → доменное исключение по таблице ниже.
3. `HTTP 200`, но `meta.status != "ok"` → `CheckoApiException` (неожиданный ответ, в лог —
   `meta.message`).
4. `HTTP 200` и `meta.status = "ok"`, но `data` пуст → `ResourceNotFoundException`.

| HTTP | `meta.status` | Исключение | Наш HTTP | Комментарий |
|------|---------------|------------|----------|-------------|
| 200 | ok | — | 200 | успех, кэшируем |
| 200 | error | `CheckoApiException` | 502 | неожиданный формат, логируем `message` |
| 401 | error | `AuthException` | 401 | «API-ключ не действителен» / «Не указан API-ключ» — проверено |
| 403 | error | `AuthException` | 401 | ключ заблокирован / нет доступа к методу (проверить на реальном ключе) |
| 402 | error | `CheckoApiException` | 502 | исчерпан баланс (проверить на реальном ключе) |
| 404 | error | `ResourceNotFoundException` | 404 | объект не найден |
| 429 | error | `RateLimitException` | 429 | превышен лимит 32 rps с IP — проверено по докам |
| 5xx | — | `CheckoApiException` | 502 | **без ретраев**: 5xx не тарифицируются, но и пользы от повтора нет |

Строки с пометкой «проверить на реальном ключе» нужно подтвердить при первом платном запросе:
коды 402/403 checko в публичной документации не фиксирует.

## Что важно знать о лимитах и оплате

- Бесплатно — 100 запросов в сутки, далее платно; **оплачиваются только ответы `200`**,
  `4XX`/`5XX` — нет.
- Технический лимит — 32 запроса в секунду с IP, сверх — `429`.
- Поэтому 5xx не ретраим (деньги не спасает, а время теряем), а `429` не ретраим, чтобы не
  усугублять; кэш на 15 минут (ADR-0002) снимает основную нагрузку.

## Что не пробрасываем наружу

`meta.message` и ключ checko не отдаём клиенту как есть: в 502 уходит наш текст, детали —
в лог. Иначе наружу утекут внутренние сообщения и косвенно состояние баланса.
