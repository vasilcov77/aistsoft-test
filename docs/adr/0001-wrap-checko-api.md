# ADR-0001: Обертка над Checko API — архитектура Transport / Resource-strategy / DTO / Facade

- **Статус:** Принят
- **Дата:** 2025-11-25
- **Автор:** проект aistsoft-test (тестовое задание)
- **Связанные документы:** [GLOSSARY.md](../GLOSSARY.md), [AGENTS.md](../../AGENTS.md)

## Контекст

Тестовое задание: REST API на PHP для получения данных с ресурса checko.ru, оформленное
в стиле ООП без использования готового фреймворка. Требуется:
- класс для внешних запросов («точка доступа с ресурсами»);
- класс получения данных с целевого ресурса;
- читабельный, чистый код;
- продуманная логика обработки ошибок;
- корректное взаимодействие с целевым ресурсом и обработка данных.

Ресурс checko.ru предоставляет платный REST API:
- базовый адрес — `https://api.checko.ru/v2/` (версия 2.0–2.5);
- все запросы — `POST`, тело `application/json`;
- ключ авторизации (`key`) передается в теле запроса;
- набор ресурсов: `/company`, `/entrepreneur`, `/person`, `/finances`, `/reliability`,
  `/timeline`, `/legal-cases`, `/enforcements`, `/contracts`, `/fedresurs`,
  `/bankruptcy-messages`, `/inspections`, `/bank`;
- тарификация — за каждый запрос.

## Решение

Строим ООП-архитектуру: ядро из четырёх слоёв + HTTP-слой сверху, на базе паттерна **Strategy**:

1. **Transport (точка доступа с ресурсами).** Единый entry point для внешних запросов —
   обёртка над Guzzle. Отвечает за HTTP-транспорт, таймауты и ретраи. Не знает, что такое
   «компания» или «договор» — он работает с абстракцией `ResourceInterface`.

2. **Resources (стратегии).** По одной реализации на эндпоинт checko. Каждая стратегия знает:
   - `getPath(): string` — относительный путь ресурса;
   - `buildParams(array $input): array` — формирует тело запроса;
   - `mapResponse(array $json): DTO` — превращает сырой ответ в доменный объект.

3. **Facade / Client.** Собирает конвейер: валидация входа → маппинг параметров → вызов
   Transport → кэш → маппинг ответа. Управляет политикой ретраев и переводит ошибки
   транспорта в доменные исключения.

4. **DTO (Value Objects).** _Immutable_ объекты данных, которые валидируют себя при создании
   (отклоняют некорректные входные данные).

Слои API (HTTP): роутер + контроллеры под префиксом `/api/v1/`, отдающие JSON.

Зависимости: **Guzzle** (HTTP-клиент), **Valkey** (кэш, через абстракцию PSR-16, TTL 1 час — см.
ADR-0002). Токен — из переменной
среды (`env`), проверка наличия при старте (fail fast).

### Почему так

- **Strategy** даёт открытый/закрытый принцип: добавить новый ресурс checko = добавить один
  класс без изменения Transport и Facade. Это прямо показывает понимание ООП.
- **DTO-объекты с внутренней валидацией** изолируют «плохие данные» от бизнес-логики.
- **Transport как единая точка доступа** разделяет транспортные детали и домен.
- **Абстракция кэша по PSR-16** не привязывает решение к Valkey напрямую; политика кэша
  (TTL 1 час, ключ без API-ключа) — в [ADR-0002](0002-cache-policy.md).

## Последствия

- Новый ресурс добавляется добавлением одного класса-стратегии + одного DTO.
- Ретраи и таймауты сосредоточены в Transport — их легко тестировать и менять.
- Кэш по PSR-16 позволяет заменить Valkey на другой бэкенд без правки домена.
- Минус: больше классов, чем в «плоском» скрипте, но это плата за чистоту и расширяемость.

## Ретраи (детализация решения)

Ретрай — только на таймаут/ошибки соединения (`ConnectException`), 3 попытки с экспоненциальной
задержкой. После исчерпания — логирование и поднятие `TimeoutException`. 5xx от checko
не ретраим: они не тарифицируются, но повтор обычно бесполезен и только задерживает ответ.

## Маппинг ошибок → HTTP

В коде это одна `ApiException` с фабриками; в ответе `error.type` сохраняет имена ниже.

| Исключение | HTTP | Причина |
|------------|------|---------|
| `InvalidInputException` | 422 | Некорректный вход (напр. плохой ИНН в DTO) |
| `AuthException` | 401 | Недействителен ключ checko |
| `ResourceNotFoundException` | 404 | checko ничего не нашёл |
| `CheckoApiException` | 502 | Некорректный/неожиданный ответ checko |
| `RateLimitException` | 429 | Лимит запросов от checko |
| `TimeoutException` | 504 | Таймаут после 3 ретраев |

Единый `ExceptionHandler` внизу роутера ловит всё и отдаёт
`{ "error": { "type", "message", "code" } }`.

Как именно ошибки checko распознаются (HTTP-код + `meta.status`, примеры ответов, лимиты и
оплата) — в [checko-api-errors.md](../checko-api-errors.md).

## Альтернативы, которые рассматривались

- **Парсинг HTML вместо обертки API** — отклонено: checko имеет официальный API.
- **Hand-rolled HTTP на stream_context** — отклонено: Guzzle даёт ретраи, таймауты, тестирование.
- **Единый большой DTO вместо per-resource** — отклонено: у ресурсов разные формы ответов.
